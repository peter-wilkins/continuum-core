# Founding Discussion Capture

## Key insight

The system should remove two cognitive taxes:

1. deciding when to record
2. deciding when to search

The resulting model is:

- always recording
- always searching

## Important distinction

This is not intended as:

- social recording
- surveillance
- passive train/bus recording

The intended mode is closer to:

> intentional cognition mode

Examples:

- driving
- walking
- workshop work
- planning
- thinking quietly
- problem solving

## Resume concept

"Resume" emerged as a stronger framing than:

- search
- open
- find
- history

Because it implies:

- continuity
- momentum
- prior understanding
- low startup cost

## Re: as protocol

The `Re:` concept emerged from email threading semantics.

Humans already understand:

- Re:
- Fwd:
- subject continuity

This may provide a natural spoken protocol for continuity systems.

## Important philosophical shift

The user may think they are resuming literal threads.

Internally there may be no literal thread structure at all.

Instead the system may construct a Resume Brief dynamically from:

- semantic similarity
- temporal proximity
- unresolved tasks
- entity links
- recency
- salience

## No UI

The phrase "there is no UI" was used philosophically.

Meaning:

- the interface disappears into intent
- the user remains in cognition mode
- software maintenance burden disappears

The real enemy is not visible UI itself.
The real enemy is maintenance friction.

## Strategic implementation advantage

A reduced UI surface area also reduces:

- frontend complexity
- state management burden
- onboarding burden
- maintenance cost
- QA complexity
- support burden

This enables small teams to focus primarily on intelligence quality.

## Important warning

Avoid prematurely rebuilding:

- folders
- dashboards
- timelines
- tagging systems
- project administration UI

Every manual organisational control risks reintroducing maintenance burden.
